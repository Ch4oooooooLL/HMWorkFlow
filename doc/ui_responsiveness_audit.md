# UI 响应性与 Python 启动检查

日期：2026-07-14

## 检查结论

| 检查点 | 原风险 | 处理结果 |
| --- | --- | --- |
| HyperMesh 原生选择面板 | 工具箱 Tk 窗口永久置顶，可能遮住原生 modal 面板，看起来像卡死 | 新增公共 `::HWFlow::nativeMarkPanel`：释放 grab、临时取消置顶并隐藏已映射工具窗口，结束/异常后恢复 |
| 工具箱其他选择入口 | 多个模块直接调用 `*createmarkpanel`，存在同类风险 | 全仓库 Tcl 入口统一改用公共包装；底层仅保留一个经过保护的直接调用 |
| Python 调用 | Tcl 同步 `exec` 会停止 Tk 事件处理；`python.exe` 会显示控制台 | Windows 强制映射到 `pythonw.exe`，后台启动并重定向日志；通过原子完成状态文件回收结果 |
| Python 等待 | 忙等或阻塞等待会冻结进度窗口 | 使用短周期 `after`/`vwait`，等待期间持续读取 `progress.json` 并处理 UI 事件 |
| Python 探测 | 每阶段重复同步启动解释器 | 无窗口后台探测，5 秒上限；成功命令在当前模块会话内缓存 |
| 大范围连接关系导出 | Tcl 先构造完整内存列表，逐 element 查询期间无反馈 | CSV 流式写入，64 KiB 缓冲，每 500 个 element 更新进度并检查取消 |
| 大范围节点导出 | 每节点三次查询且无反馈 | 优先一次 `hm_nodevalue`，失败时兼容回退；每 1000 个节点更新进度并检查取消 |
| 保护节点核验 | 大区域逐节点扫描期间界面无反馈 | 每 500 个节点让出 UI 事件并检查取消 |
| 图形编号显示 | 对数万 element 执行 `*shownumbers` 会严重拖慢图形刷新 | 仅在不超过 200 个 ID 时显示逐单元编号，大集合只保留 mark 和视图定位 |
| 运行中重复操作 | 重复检查、选择、恢复、关闭可能争用 mark 或模型状态 | 增加运行状态门禁；关闭动作先请求停止，等待不可中断的原生命令返回 |
| 质量检查、拓扑动作、任务前/后模型保存 | HyperMesh 原生命令本身可能长时间不可中断 | 调用前显示明确阶段并刷新界面；任务中不写区域/轮次快照，命令返回后立即检查取消并按需恢复任务前模型 |
| 模型覆盖/替换确认 | `*writefile` 目标已存在或 `*readfile` 替换修改模型时，原生确认框可能藏在进度窗口后 | 删除任务拥有的旧输出，并在读写前调用 `hm_answernext yes`；错误进入日志，不弹模态框 |
| 完成/错误消息 | `tk_messageBox` 阻塞 Tcl 调用链，且可能位于其他置顶窗口后 | 局部优化模块不再调用模态消息框；使用状态区、命令流和日志，完成后的进度窗口由用户关闭 |
| 优化进度仅滚动日志 | 区域内动作快速刷屏，原生复检固定写回 15%/25%，导致百分比倒退且无法判断剩余工作 | 为区域、轮次和子阶段分配单调区间；动作最多约 20 批刷新；显示计数、耗时和 ETA；局部/最终复检使用调用方传入的区间 |
| criteria 重复读取 | 每个区域、每轮复检都执行 `*readqualitycriteria`，检查与优化割裂 | 按路径和修改时间缓存已加载上下文；首轮复用检查结果，修改后才复检；计划参数变化时自动重建 |
| Washer 自动修改风险 | Washer 环属于连接/孔边敏感网格，通用拓扑动作不适合默认处理 | 默认复用现有 Washer 识别器排除相应层，并单独输出 ID 和报告计数；用户可明确关闭开关 |

## 已知边界

`hm_getelementsqualityinfo`、`*splitelements`、Element Quality 修改命令、`*writefile` 和 `*readfile` 都在 HyperMesh 进程内部同步执行。Tcl 无法在不破坏模型一致性的前提下强杀这些命令，因此执行期间可能暂时不能响应“停止”；界面会在调用前明确提示，命令返回后再执行取消并恢复任务前模型。

`eval *createmark` 对超大显式 ID 列表仍可能耗时。当前没有在 HM2019 实机验证可替代的批量追加 mark 签名，因此没有引入未经验证的命令。组件、显示范围和全模型范围应优先使用 HyperMesh 原生的按条件建 mark。

## 实机复核项

1. 在 HyperMesh 2019 中逐个打开组件、element、surface 和 entity 选择入口，确认工具窗口隐藏、选择面板可见、中键/Esc 后窗口恢复。
2. 使用大壳模型运行“检查质量”，观察连接关系和节点导出期间进度窗口可拖动、停止按钮可提交取消。
3. 在 Windows 任务管理器确认后台进程为随包 `pythonw.exe`，运行期间没有命令提示符窗口。
4. 对长时间原生质量检查和拓扑动作验证提示语、返回后的取消和任务前模型恢复行为，并确认无区域/轮次 `.hm` 文件。
